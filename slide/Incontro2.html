Perché un sistema di controllo di versione

  • Registra ogni modifica ai file di un progetto: chi, quando, cosa e perché.
  • Permette di tornare indietro a una versione precedente senza copie finale_v2_DEFINITIVO.py.

lab6/incontro-2/github/01-git/02-centralizzato-distribuito.md

Centralizzato o distribuito

Centralizzato (CVS, Subversion)

  • Un solo server con la storia
  • Senza rete non si registrano versioni
  • Se il server si guasta, la storia è a rischio

Distribuito (Git, Mercurial)

  • Ogni copia contiene tutta la storia
  • Si lavora e si fa commit anche offline
  • La copia su GitHub è solo quella condivisa

lab6/incontro-2/github/01-git/13-tornare-indietro.md

Tornare indietro senza fare danni

git reset --hard

  • Cancella commit dalla storia
  • Se la storia era già su GitHub crea problemi a chiunque l'abbia scaricata
  • In aula: no

git revert <hash>

  • Aggiunge un commit che annulla un commit precedente
  • La storia resta leggibile
  • In aula: sempre questo

Il revert di un commit di merge richiede l'opzione -m: in aula si annullano commit normali.

GitHub Actions

Automazioni che partono da un evento del repository (push, pull request, apertura di un'issue, orario…).

Workflow: file YAML in .github/workflows/.
Job: un gruppo di passi eseguiti su un runner (una macchina virtuale di GitHub).
Step: un comando o un'azione già pronta dal Marketplace.

Usi tipici: eseguire i test, pubblicare un sito, controllare lo stile del codice.

Il workflow del repository demo

# .github/workflows/test.yml
name: Test
on: [push, pull_request]          # quando parte
jobs:
  test:
    runs-on: ubuntu-latest         # dove gira
    steps:
      - uses: actions/checkout@v4          # scarica il repository
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - run: pip install pytest
      - run: pytest -q verifiche/test      # 16 test

Segno verde: 16 test superati. Con l'errore dello studente A: croce rossa, 7 test falliti su 16.
